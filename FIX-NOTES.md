# Audit & Fix Notes — ESP32 Smart Healthcare Project

This file documents what was checked and what was changed in this project export.

## What was found (audit)

1. **MAX30102 (heart-rate / SpO2 sensor) was missing from the actual wired circuit.**
   The schematic and BOM report referenced it, and the firmware code checks for it,
   but the real breadboard/3D wiring (`wiring/wiring.json` — the file that actually
   drives the 3D view, ERC, and part list) never included it. This meant the
   downloadable circuit did not match the report or the firmware.

2. **I2C bus pull-up resistors (4.7kΩ on SDA and SCL) were designed but not wired.**
   Not strictly required for a single-device I2C bus (ESP32's internal pull-ups
   often suffice), but recommended now that two devices (MPU6050 + MAX30102)
   share the same SDA/SCL lines.

3. Everything else — pin mapping, DS18B20 wiring, SOS button, buzzer, LEDs,
   debounce/alert logic, and the Wi-Fi/HTTP telemetry layer in the firmware — was
   checked and is correct, with no changes needed.

## What was fixed

In `wiring/wiring.json`:
- Added **MAX30102** (`max_1`), wired with flying leads (same style as the
  DS18B20 probe):
  - VIN → 3.3V rail
  - GND → GND rail
  - SDA → row 30 (same electrical row as MPU6050's SDA → ESP32 GPIO21, so it
    correctly joins the existing I2C bus)
  - SCL → row 31 (same row as MPU6050's SCL → ESP32 GPIO22)
- Added a **100nF decoupling capacitor** (`c_max`) across MAX30102's VIN/GND —
  standard practice for sensor ICs, reduces power-supply noise.
- Added two **4.7kΩ pull-up resistors** (`r_sda`, `r_scl`): one leg on the
  SDA/SCL bus row, the other leg routed to the 3.3V rail — the correct way to
  wire a pull-up on a breadboard (the two legs must be on different rows, or
  you short the resistor out).

In `src/config.h`:
- Added a comment reminder to replace `WIFI_SSID`, `WIFI_PASSWORD`, and
  `BACKEND_URL` with real values before flashing physical hardware.

## What you should still do

- **`docs/simulation-report.md` is now stale** — it was generated by tinkered.ai
  before this fix, so its SPICE/operating-point numbers don't reflect the
  updated circuit. Re-import this project into tinkered.ai and let it
  regenerate that report — don't rely on the old numbers.
- Re-run **ERC** in tinkered.ai after importing this fixed project to get a
  fresh pass/fail confirmation.
- When you wire the **real physical breadboard**, MAX30102's SDA/SCL just need
  to land on the same rows as MPU6050's SDA/SCL (or directly on the ESP32's
  GPIO21/GPIO22 if you prefer daisy-chaining differently) — any hole in the
  same row works, since a breadboard row is one electrical node.
